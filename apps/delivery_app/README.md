# Delivery App (Flutter)

Customer, driver, restaurant and admin client for the platform in
`services/`, talking to everything through the gateway at `:8080`.

## First-time setup

Only `lib/` and `pubspec.yaml` are checked in — the native Android/iOS/web
platform folders are generated by the Flutter tool itself, not hand-written,
so run this once after cloning:

```bash
flutter create --platforms=android,ios,web .
flutter pub get
```

`flutter create` on an existing project only adds the missing platform
folders; it will not touch `lib/`.

Then add two permissions `flutter create` doesn't add on its own:

- **Android** (`android/app/src/main/AndroidManifest.xml`): add
  `<uses-permission android:name="android.permission.INTERNET" />` and
  `<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />`
  inside `<manifest>`.
- **iOS** (`ios/Runner/Info.plist`): add `NSLocationWhenInUseUsageDescription`
  with a short reason string.

## Running

```bash
# Web (talks to http://localhost:8080 directly)
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8080

# Android emulator (10.0.2.2 is the emulator's alias for the host machine)
flutter run -d emulator-5554
```

The gateway must already be up (`docker compose up`) and seeded
(`infra/seed/seed.sh`) before logging in.

## Structure

- `lib/models/` — plain classes with hand-written `fromJson`, matching each
  service's JSON response (no code generation step).
- `lib/core/api_client.dart` — one Dio client, attaches the stored JWT.
- `lib/providers/providers.dart` — Riverpod: auth state, one repository per
  backend service, and the WebSocket stream for live order tracking.
- `lib/screens/` — one folder per role: `auth`, `customer`, `driver`,
  `restaurant`, `admin`.
